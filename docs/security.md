# Substation Cybersecurity, RBAC & Prompt Injection Defense

## 1. Role-Based Access Control (RBAC)

The service layer defines three operational roles. Write APIs authenticate through configured API keys and derive the role server-side; legacy role and username fields in request bodies are ignored. This is a lightweight demo authentication boundary, not a replacement for an enterprise identity provider:

| Role | View Incidents & Waveforms | Run Investigations & Validations | Submit Simulated Actions | Approve Simulated Control |
| :--- | :---: | :---: | :---: | :---: |
| **VIEWER** | Yes | No | No | No |
| **ENGINEER** | Yes | Yes | Yes | No |
| **APPROVER** | Yes | Yes | Yes | Yes (Two-person rule) |

---

## 2. Non-Bypassable Simulation Wall
- GridLens operates in an educational/simulation sandbox and **never controls real physical electrical apparatus**.
- All control recommendations generated by the AI are tagged `SIMULATED_ACTION`.
- The service-level approval queue requires a token generated by a distinct user holding the `APPROVER` role (two-person rule: requester cannot approve their own action). There is currently no live-action execution endpoint.

---

## 3. Prompt Injection Defense Architecture
- Substation automation systems ingest untrusted external text (COMTRADE station comments, relay event descriptions, operator logs, vendor PDF manuals).
- The sanitizer provides pattern detection and control-character removal, but it must be wired into every ingress path before this can be called an end-to-end defense.
- The final report path is deterministic and does not use an LLM to invent measurements.

Before production deployment, add an identity provider, server-side role lookup, strict CORS origins, persistent audit logs, key management, request limits, and a security review.
